## 一、三层自我改进（必须先分清，否则会一直在最底层打转）

| 层 | 名字 | 改什么 | 谁负责 | 当前状态 |
|---|---|---|---|---|
| L1 | 一阶优化 | **策略参数**（max_positions / momentum_* / atr_stop_mult …） | AM-EVOLVE 11:40、PM-EVOLVE 周三18:00 | **已饱和**：R40/R41 证参数空间无可挖 alpha |
| L2 | 二阶优化 | **改进流程本身**：目标函数、验证器、搜索空间、观测、账本 | **RSI 每周六 11:00** | 首跑完成，识别 7 类缺陷（§3）；**第 1 条已交付**（搜索空间契约，§4） |
| L3 | 三阶（元-元） | 判断「L2 的改动是否真的提升了后续 L1 的命中率」，不行就回滚 | RSI 的长期职责 | 尚未建立度量（§4 第一条） |

**为什么必须往上走一层**：L1 每次迭代都依赖 L2 提供的「尺子」。
尺子若不准（基线漂移、指标是划分假象、搜索空间含死键），
L1 越勤奋，错误结论积累得越快。R39/R40/R41 三轮的反复证伪，本质都是**尺子问题**。

## 四、路线图（每周只做一条，可归因）

### ✅ P1-a′ 搜索空间契约（R43，2026-10-28 已交付）

把「每个生产参数究竟被谁读」变成**可计算事实**，并用测试钉住显式清单。

- 单一事实源：`strategy/_param_audit.py`
  - `identifiers()`：AST 级识别四种读取形态（字符串常量 / 属性 / 关键字实参 / Name），
    注释与散文天然不计；
  - `_collect()`：全仓库扫描 − 排除目录（`tests/scripts/config/docs/reports/...`）；
  - `classify()` → 五分类：双向可验证 / 别名可验证 / 仅实盘 / 仅回测 / 死参数；
  - `contract_violations()`：**双向**校验（错登记 + 漏登记都算违规）。
- 守卫：`tests/test_search_space_contract.py`（12 用例）
  - 正向对照 `test_detector_is_not_degenerate`：可验证占比 ≥40% + 12 个历史主战场旋钮逐个点名
    ⇒ 防「检测器坏了、契约跟着坏」的合谋式假绿；
  - 自污染守卫 `test_self_module_is_excluded_from_scan`：本模块列出全部参数名，
    若不排除自己，3 个死参数会静默变「仅实盘」；
  - 防分裂 `test_meta_audit_script_reuses_this_module`：元审计脚本不得再自带副本。
- 效果：**「网格 dSh 恒 0.000」不再允许直接写成「已证伪」** —— 先查契约，
  仅实盘 ⇒ 记「未验证」；死参数 ⇒ 该轴不该开工。
- 验收：全量 627 通过 / 0 失败；P0 逐位不变（IS +301.05% / Sh 1.93 / MDD −12.97%）。

### P0-a 把 `base_cfg()` 改为从 settings 自动派生 + 漂移守卫测试
- 做法：新增 `strategy/_cfg_source.py::config_from_settings()`，字段同名直接映射、
  已知别名走显式表（`fixed_amount←max_order_amount`、`consec_loss_trigger←max_consecutive_losses`、
  `daily_loss_pct←daily_loss_limit_pct`），研究专用开关进显式 `IGNORE` 白名单并注明理由；
  加 `tests/test_base_cfg_no_drift.py`：任何字段与 settings 不一致即失败。
- 效果：**尺子无法再漂移**，此后所有增量都可跨轮比较。
- 验收：本审计 L2 的「未映射 75」降到「IGNORE 白名单」大小，且漂移恒为 0。
- ⚠ 开工前必读：`tests/test_evolve_baseline_sync.py` 已覆盖 ~50 个同名字段，
  真实缺口只有别名的 3 对，而那 3 对指向的闸门在 P0 中**本就关闭**
  ⇒ 收益（dSh 可信度）可能显著低于预期，排序时可下调。

### P0-b 账本结构化，让「命中率」可算
- 做法：`EVOLUTION_DECISIONS.md` 每轮追加固定字段（round / candidate / 验证器 / IS / OOS /
  verdict / landed / 事后是否被推翻 / 若否决属「方向错」还是「尺子错」）；
  新增 `scripts/_ledger_stats.py` 输出：命中率、按原因分类的否决率、churn 次数。
- 效果：L3 度量成立 —— 才能判断 §四 的改动是否真的让后续轮次更准。

## 六、附：Relative Strength Index 那条研究的结论（已闭合）

`scripts/_rsi_evolve.py` 于 2026-10-28 首跑，结论 **NO-GO**，不再排期：
- `settings` 的 `rsi_period/oversold/overbought` 在日线闸门链**无读取点**（与 §2.1 死参数一致）；
- 候选池 RSI(14) 最小 48.4、中位 65.2 ⇒「超卖」桶零样本，抄底逻辑在本策略中不存在；
- 唯一显著结果**反向**：`RSI≤55` 过滤使 Δ20d = −6.01%（p=0.0026）；
- `corr(RSI, mom60)=+0.40` ⇒ 弱动量代理，非独立因子。
- 护栏：**禁止新增 RSI 上界过滤 / 超买剔除**。
