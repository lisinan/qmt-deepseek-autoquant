## 一、模式门禁（MODE GATE）—— 不得再写死 paper

1. **当前模式 = `live`（真实资金）**。依据：2026-10-29 15:05 OWNER 明确指令切换，

2. 门禁的语义改为**「与 OWNER 最近一次明确指令一致」**，而不是「等于 paper」：
   - 读 `config/settings.py::EXECUTION_MODE`，与本文档 §一.1 记录的模式比对；
   - **一致** → 正常继续；
   - **不一致**（例如被静默改成 paper，或出现第三种取值）→ 输出一行 `[MODE-ALERT]`，
     说明当前值与契约值，**然后继续执行只读部分**，不要整体停机（停机＝把安全网自己关掉）。
3. **任何自动化都不得写入 / 切换 `EXECUTION_MODE`**，包括「顺手改回去」。

   若 settings 被改成 paper，live 引擎会被**静默重启成 paper** —— 这是改这一行的真实风险。
4. **live 下的行为边界**：
   - 允许：全部只读分析、回测、写报告、写账本、修工程缺陷、跑测试、本地 commit。
   - 禁止：下单 / 撤单 / 改持仓 / 改券商连接 / 改 `EXECUTION_MODE`。
   - 需要重启才生效的改动 → **只提示，不代劳**（重启属 OWNER）。

### 3.4 P0 基线一致性：**三态**判定（2026-11-08 R50-RSI）

验证器基线（`strategy/_evolve_wf.py::base_cfg()`）是生产配置的手抄镜像，
「不等于生产」**不一定**是缺陷，也可能是**刻意的**。故一律按三态报：

| 态 | 判据 | 处置 |
|---|---|---|
| **一致** | 逐字段值相等（`[]` 与 `()` 视为相同） | — |
| **已声明分歧** | 不等，但值**逐位等于** `config/_baseline_divergence.py::KNOWN_DIVERGENCE` 登记的那一对值 | 报告里列表说明理由，**不计入漂移、不占优先级** |
| **★漂移** | 不等且未登记，或值偏离登记值 | **唯一该占 P0 首位**的一类 |

1. **登记表是唯一事实源**：`tests/test_evolve_baseline_sync.py` 与
   `scripts/_recursive_self_improve.py` 都 import 它，**不得再有第二份字面量**。
   守卫：`tests/test_rsi_baseline_declared.py`（5 例，含 `is` 同一性断言）。
2. **豁免只对登记的「具体值」生效**，不得改成按字段名豁免：生产多一只观察篮、
   或回测基线把探针抄进去，都必须立刻回到 ★漂移（反向对照已入测试）。
3. 为什么要分这一态（实证）：`manual_entry_codes`（回测 `()` / 生产 `['510050.SH']`，
   510050 是 live 链路探针、不进回测宇宙）在旧二态下被 R49、R50 连续两轮报成
   **P0 首位**，而它**修不了** —— 修它要么把探针抄进 P0 基线（污染基线，
   2026-11-05 OWNER 已裁决不放开），要么丢掉唯一的 live 对账对象。
   ⇒ 结果是真正的漂移即便出现也挤不到第一优先级。与 GUARD 每小时假告警同型：
   **一个永远报红的指标等于没有指标**。
4. 新增「已声明分歧」必须写清三件事：为什么刻意不同、谁裁决的（日期）、
   什么条件下应重新裁决。缺任一条不得登记。



## 四、发现路由与活性（ROUTING & LIVENESS）

### 4.1 发现必须有人消费
任何任务产出发现后，除写自己的报告外，**必须**在 `reports/OWNER_INBOX.md` 追加一行：

```
- [P0|P1|P2] [SAFE|FORBIDDEN|INFO] <一句话结论> — <证据文件>:<行/字段> — 发现于 <任务名> <日期>
```

- **SAFE**：纯工程/正确性/观测修复，可自动落地（改完必须 `tests/run_all.py` 全绿）。
- **FORBIDDEN**：改策略参数 / 改模式 / 需重启 / 真实资金操作 ⇒ 只报给 OWNER，不得自行执行。
- **INFO**：观察项。
- **17:00 工程维护**是当日**汇总去重**负责人：读当日全部报告 → 合并 INBOX → SAFE 项当场修 →
  FORBIDDEN 项在输出里点名。**资金安全级（P0）必须出现在当日输出首屏**。

### 4.2 活性自检（**活性三态**，R49-RSI 2026-11-01 升级）
1. 开工先看自己 `memory.md` 末条日期；若距今天 > 3 天，在输出**首行**写
   `⚠ 本任务已停摆 N 天（上次 <日期>）`。停摆本身就是最该报的发现。
2. **判定一律用三态，不得再用「最近运行时间」单指标**（那是 R44 及以前的做法）：

   | 态 | 定义（同时满足） | 含义 |
   |---|---|---|
   | ① 正常产出 | 应跑槽位之后写过 memory，末条**无**停机标记（或窗口内有产物） | 做了事 |
   | ② 运行但自我停机 | 槽位之后写过 memory **且** 末条含停机标记 **且** 槽位窗口内无产物 | **在跑但什么都没做** |
   | ③ 完全未运行 | 槽位之后既无 memory 也无产物 | 没跑 |

   - **停机标记**（强标记，只收「本次运行明确什么都没做」的措辞）：
     `[MODE-ALERT]` / `整体停机` / `自我停机` / `硬闸门` / `闸门拦截` / `闸门未通过` /
     `立即停止` / `停止一切落盘` / `不执行 Step` / `只读+顶部告警`。
     **例外**：`[GUARDIAN-ALERT]` 对 GUARD 是**假告警**（它做了 health_check，只是多打一行），
     不计入停机判据 —— 否则每小时误报一次 ②，正是「用假告警把安全网自己关掉」。
   - **槽位**按本契约 §五 的时段表算（`scripts/_loop_liveness.py::TASKS`），
     **不按 rrule 字面**：GUARD 的 rrule 是全天每小时，但职责只到 15:00。
   - **产物窗口必须贴槽位**（槽位后 0~4 小时）。用「到 now 为止」会把周末补跑/次日
     其它任务的文件当成本槽位产物 ⇒ 真实停摆被洗成 ①。
   - ③ 在「非交易日」不产生槽位（`core/market_calendar.is_trading_day`），
     休市日不得判为漏跑。
3. **②③ 必须给出归因**（这是本条的全部价值：修复对象完全不同）：
   - `prompt_gate`：memory 里自己写了门禁/停机 ⇒ 改 prompt 门禁（本契约 §一）；
   - `machine_sleep`：槽位窗口内 `logs/guardian.log` **无 300s 心跳**（或空档 > 15 分钟）
     ⇒ 整机休眠/关机，**不要改代码**，调时段或提醒 OWNER 别关机；
   - `awake_no_artifact`：心跳连续（机器醒着）却零产物零留痕 ⇒ 任务自身/宿主未触发。
4. **首段点名**：任何 ②③ 必须出现在报告**第一个小节**（`RSI_META_LATEST.md` §〇 与
   `reports/OWNER_INBOX.md`），不得只写进明细表。历史教训：METRIC-HYGIENE 把
   资金安全级发现写在报告中部，17:00 汇总直接漏读。
5. 实现与守卫：`scripts/_loop_liveness.py`（唯一实现）+ `tests/test_loop_liveness.py`
   （15 例，含「同一份没跑事实喂不同心跳必须得到不同归因」的反向对照）。
   **主审计脚本只 import，不得自带第二份判据**（第 24 条：两份实现必然静默漂移）。
6. 周末/节假日任务避开机器休眠时段：证据 2026-10-31（周六）10:00 SYNTHESIZE 与 11:00 RSI
   因**整机休眠**全部未执行（`logs/guardian.log` 当日只有 00:25 与 23:22 两条心跳）。
   故周度任务放在**周日 20:00 / 21:00**。
7. ★ **已知待修（2026-11-08 R50 实测，下一轮第一顺位，勿再当成「任务真停了」）**：
   ② 的两个必需条件都会被**自身产物**伪造，实测本任务自己被误判为 ②：
   - **标记来自「讨论标记」**：`halt_hits()` 匹配的是 memory 末条的原文，而 R49 的记忆
     正文里在**描述**这批标记（引用了 `[MODE-ALERT]`、`整体停机` 等字样）⇒ 判据命中自身文档。
     同理，任何任务只要在记忆里复盘「今天差点撞门禁」，下周就会被判 ②。
   - **产物被下一次运行覆盖**：`product_fresh()` 用 mtime 判窗口，而 RSI 的产物名固定
     （`reports/meta/RSI_META_LATEST.md`），下周重跑即抹掉上周的证据 ⇒
     上周明明写了 431 行模块 + 报告，仍被判「窗口内无产物」。
   ⇒ 修法方向（不是加 ignore 名单，那只会扩大盲区）：标记必须在「结论位置」才算
     （如首行 / 状态行），或排除反引号与引号内的引用；产物判据改「当日归档案」
     （`RSI_META_YYYYMMDD.md` 快照）或接受 memory 里的落地清单作证据。

### 4.3 误诊防范：先分清「机器休眠」vs「引擎故障」

1. `logs/guardian.log` 是否有 300s 心跳 → 无心跳 = 整机休眠/关机，不是引擎问题；

3. 两者都在、但无业务轮次 → 才是时段守卫 / 主循环问题。

诊断为「引擎时段守卫重启后唤醒逻辑缺陷」，**误诊**。真实原因是 11:47–17:24 整机休眠
